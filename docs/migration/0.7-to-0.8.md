# 0.7.0 → 0.8.0 마이그레이션

`0.8.0`은 호환 계층이 없는 breaking 릴리스다. deprecated alias나 typealias를 제공하지 않으므로,
아래 rename을 모두 적용해야 컴파일된다. 대신 변경은 전부 기계적이며 동작이 달라지는 항목은 마지막
절에만 있다.

Maven 좌표는 `0.7.0`과 동일하다.

```kotlin
implementation("io.github.kez-lab:compose-pickers:0.8.0")
```

## 1. Kotlin package rename

모든 public API가 `com.kez.picker`에서 `io.github.kezlab.compose.pickers`로 이동했다.

```diff
-import com.kez.picker.time.TimePicker
-import com.kez.picker.time.rememberTimePickerState
+import io.github.kezlab.compose.pickers.time.TimePicker
+import io.github.kezlab.compose.pickers.time.rememberTimePickerState
```

프로젝트 전체 치환으로 처리할 수 있다.

```bash
grep -rl 'com\.kez\.picker' src \
  | xargs sed -i '' 's/com\.kez\.picker/io.github.kezlab.compose.pickers/g'
```

## 2. `Picker` → `WheelPicker`

generic single-column composable이 하나로 정리됐다. `Picker`는 공개 API에서 제거됐고
`WheelPicker`만 남는다.

`Picker.onSelectedItemChange`는 interaction이 settle된 뒤에만 호출됐다. `WheelPicker`에서
`onSelectedItemChange`는 scroll 중 중앙 item이 바뀔 때마다 live로 호출되고, settle된 값은
`onSelectionSettled`로 전달된다. 따라서 기존 동작을 그대로 유지하려면 live callback을 비우고
settled callback만 처리한다.

```diff
-Picker(
+WheelPicker(
     items = items,
     selectedItem = selected,
-    onSelectedItemChange = { selected = it },
+    onSelectedItemChange = {},
+    onSelectionSettled = { if (it != selected) selected = it },
 )
```

scroll 중 값을 미리 보여주고 싶다면 오히려 새 계약이 더 단순하다. live 값은 preview에,
settled 값은 network/query 같은 비싼 side effect에 쓴다.

```kotlin
WheelPicker(
    items = items,
    selectedItem = selected,
    onSelectedItemChange = { selected = it },   // preview 갱신
    onSelectionSettled = { loadDetailsFor(it) } // 확정 후 1회
)
```

composite picker(`TimePicker`, `DatePicker`, `YearMonthPicker`, `DateRangePicker`,
`DurationPicker`)는 영향이 없다. 내부적으로 settled-only 계약을 계속 사용한다.

## 3. `util` 패키지 제거

| 0.7.0 | 0.8.0 |
| :--- | :--- |
| `...pickers.util.TimeFormat` | `...pickers.time.TimeFormat` |
| `...pickers.util.TimePeriod` | `...pickers.time.TimePeriod` |
| `...pickers.util.currentDate()` | `...pickers.currentDate()` |
| `...pickers.util.currentDateTime()` | `...pickers.currentDateTime()` |
| `...pickers.util.currentYear()` | 제거 |
| `...pickers.util.currentMonth()` | 제거 |
| `...pickers.util.currentHour()` | 제거 |
| `...pickers.util.currentMinute()` | 제거 |
| `YEAR_RANGE`, `MONTH_RANGE`, `DAY_RANGE`, `HOUR24_RANGE`, `HOUR12_RANGE`, `MINUTE_RANGE` | 제거(내부 기본값) |

제거된 `current*()` 4개는 `currentDateTime()`에서 바로 얻을 수 있다.

```diff
-val year = currentYear()
+val year = currentDateTime().year
```

`*_RANGE` 상수는 각 picker의 기본 item 목록이었다. 명시적으로 필요하면 직접 정의하거나
`PickerDefaults.timePickerItems(...)` / `datePickerItems(...)` 같은 items factory를 쓴다.

```diff
-val hours = HOUR24_RANGE
+val hours = (0..23).toList()
```

## 4. `currentDate` / `currentDateTime`의 시간대 파라미터

두 함수는 이제 `timeZone` 파라미터를 받는다. 기본값이 기존 동작인 `TimeZone.currentSystemDefault()`
이므로 호출부를 바꾸지 않아도 결과는 같다. picker가 고정 시간대나 사용자가 고른 시간대를 나타낸다면
이제 그 시간대를 명시할 수 있다.

```kotlin
val today = currentDate(TimeZone.of("Asia/Seoul"))
```

## 5. iOS `iosX64` 타겟 제거

Compose Multiplatform `1.11.0`이 `ios_x64` artifact 배포를 중단해 라이브러리도 해당 타겟을 더 이상
빌드하지 않는다. 배포되는 iOS 타겟은 `iosArm64`(기기)와 `iosSimulatorArm64`(Apple Silicon
시뮬레이터)이다. iOS 기기 빌드, App Store 릴리스, Apple Silicon 시뮬레이터 개발은 영향이 없다.
Intel Mac 시뮬레이터가 필요한 경우에만 `0.7.0`에 머물러야 한다.

## 6. 동작이 달라지는 항목

여기까지가 rename이고, 실제 동작 차이는 다음 하나뿐이다.

- `WheelPicker`의 `onSelectedItemChange`는 live callback이다. `Picker`를 그대로 이름만 바꿔
  치환하면 scroll 중에도 callback이 발생한다. 2절의 diff대로 `onSelectionSettled`로 옮겨야
  기존 동작이 유지된다.

`0.7.0`에서 `Picker` 대신 composite picker만 사용했다면 1절의 package rename만 적용하면 된다.
